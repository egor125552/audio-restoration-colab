# Разделитель песен и кэш моделей

Этот документ описывает новый экспериментальный режим из draft PR #10.

## Как работает кэш

1. При первом запуске выбранный checkpoint скачивается в общий каталог моделей Colab.
2. Разделитель запускается как отдельный постоянный процесс.
3. Повторный запуск той же задачи использует уже загруженную модель и не читает веса заново.
4. При переходе на другую тяжёлую модель предыдущая модель выгружается из VRAM, чтобы Tesla T4 не получила ошибку нехватки памяти.
5. Скачанный checkpoint остаётся на диске, поэтому возврат к нему не требует повторного скачивания.
6. Изменение mute, solo или громкости в микшере не запускает нейросеть: FFmpeg собирает новый микс из готовых стемов.

Кэш работает только пока жив текущий Colab-сеанс. После полного перезапуска среды модель нужно снова загрузить в VRAM, но сохранённые на подключённом диске веса не требуется скачивать повторно.

## Длинные треки

Длинные записи обрабатываются последовательно крупными частями. Одна и та же загруженная модель используется для всех частей, а пиковый расход видеопамяти не должен расти пропорционально длительности песни.

## Качество

По умолчанию используется сбалансированный режим. Максимальное качество увеличивает размер и перекрытие спектральных фрагментов и может отключать autocast там, где это поддерживает backend. Такой режим медленнее и требует больше VRAM.

## Статус

Функция остаётся экспериментальной до проверки каждого семейства моделей на реальной Colab Tesla T4, прослушивания результатов и тестирования клавиатуры с VoiceOver.
